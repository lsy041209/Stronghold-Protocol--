### 新功能

- **插件载荷切实落地**：我们的六组定制功能随包挂载并可验收 ——
  ①我方功能面文件在位 ②房间聊天（服务端协议 ＋ 大厅）③客户端真的能发收聊天
  ④望的跟子标记（**三处必须同时挂**，少一处就是静默空转）⑤标题页侧栏（更新公告／特别鸣谢）
  ⑥皮肤/换装的挂载（见下方"已知未完成"）。
  验收闸：`test/plugin-mount.test.js`。
- **野排（快速匹配）**：大厅新增「**快速匹配**」入口 —— 发 `room.matchmake { difficulty }`，
  服务端把同难度的公开等待房并起来；**60 秒（`matchmakeFillMs`）没人来就用 AI 补满开局**。
  ⛔ **不新造第二套协议**：房间状态继续由既有的 `room.state` 推送更新。
* 📌 **服务端那一半本来就是我们的**（`server/lobby.js` 我方独有；上游那份没有匹配）。
- **`/healthz` 新增 `matchmaking` 字段**：报**正在凑人的匹配房数**（`0 → 1 → 开局后回 0`），
  让野排**在线上就有能红的读数**。⚠️ 它**不是** `waitingRooms` 的别名：**普通等待房不计入**。
- **多语言（`public/i18n`）**：补齐 `en` / `ja` / `ko` / `zh-TW` 四个语言包（与上游逐字节相同、一个不漏）。
  ⇒ **修正了此前"只有中文"的状态**。
- **房间聊天 ＋ 房间休眠保留**：首次带密钥进房也能看到前人留言；房间空了**保留 20 分钟**
  （`roomRetentionMs`），只有房主账号重新开房能唤醒（复用房号 ＋ 聊天记录），超时删房并清空记录。
  休眠房**不计入** `/healthz` 的 `rooms`/`waitingRooms`。

### 修复

- **表情图与本地美术的扩展名回归**（玩家可见）：换基座时 `emoteArtPath` / `tools/build-emotes.mjs` /
  `data/emotes.json` / `public/js/assets.js` 的 spine 回退被**一起 revert 回上游的 `.png`**，
  而磁盘上的本地素材**全是 `.webp`**（`public/assets/local` 共 1448 个文件、`.png` 0 个）
  ⇒ 一旦载入本地客户端美术的解包清单，这些引用**全部指向不存在的文件**（镜像回退可用，故未必当场可见）。
  本轮按 **`0.1.4.1` 冷备原文**逐处改回 `.webp`。
- 🔴 **判据本身也跟着 bug 走了**，所以顺手修好判据：
  `test/ui/emotes.test.js` 的期望值改回 `.webp`，且落盘断言**从"非空读取"升级为真 WebP 容器**
  （`RIFF` / `WEBP`）；`test/ui/localArt.test.js`、`test/render/assets.test.js` 同步。
- 🔴 **三份浏览器判据的素材守卫原来找 `.png`** ⇒ 会**静默跳过**真正的断言（3 条 3D 棋盘 ＋ 1 条官方表情轮盘）
  ⇒ 改回 `.webp`（**这是"假覆盖"，不是环境噪音**）。
- **卡顿欠账被丢弃**：`server/match/fields.js` 的 `_pump` 在 `n > cap` 时写 `this.acc = 0`，
  把整段欠账抹掉 ⇒ 服务端战斗**永久落后**并与客户端分叉。已恢复为按 `MAX_CATCHUP_DEBT_SECONDS` 封顶限速推进，
  连同它的判据 `test/match/pacer-tick-drop.test.js` 一起重挂。
- **负血（我执）被治疗那半**：`sim/damage.js` 的 `heal()` 恢复"负生命优先被治疗"（并让返回值把负血治疗量计入），
  判据 `test/sim/x1-neghp-heal.test.js`（先写红探针再改）。
  ℹ️ **客户端显示负血**那一层**仍未闭环**（`sim/snapshot.js` 的下发与客户端 `units.js` 的夹取），见"已知未完成"。
- **封印/安全头**：`X-Frame-Options` 随上游的 `server/index.js` → `server/http/*` 拆分**挪到 `server/http/common.js`**。
